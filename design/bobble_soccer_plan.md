# 알까기 축구 기획서

> 레퍼런스: Discord Activity **Bobble League** 카피.
> 목표: 사이트에 붙는 가벼운 3D 웹게임, 4:4, 풋살장 크기에 큰 골대, 타격감과 효과음 위주.

---

## 1. 레퍼런스 조사: Bobble League

| 항목 | 내용 | 출처 신뢰도 |
|---|---|---|
| 정체 | Discord에서 직접 만든 Activity, 음성 채널 안에서 실행하는 테이블 위 축구 | 공식 FAQ |
| 팀 구성 | 팀당 Bobble(바블헤드 인형) **4개**, 최대 8명 플레이, 나머지는 관전 | 공식 FAQ / TV Tropes |
| 조작 | Bobble을 **클릭한 채 드래그**해서 방향과 세기를 정함 (알까기, 새총 방식) | 공식 FAQ / TV Tropes |
| 턴 구조 | **양 팀이 동시에** 이동을 계획 (팬 위키 기준 턴당 약 15초) → 시간이 끝나면 모든 이동이 **동시에 실시간 물리로 진행** | 팬 위키 / 공식 FAQ |
| 재미 포인트 | 물리가 예측하기 어려워서 **자책골이 자주 나옴**. 이 혼돈이 재미의 핵심 | TV Tropes |
| 승리 | 경기 종료 시 득점이 많은 쪽이 승리 | 공식 FAQ |
| Power Play | 수집형 아이템. 사용 방식은 3가지: 클릭해서 사용 / 필드에 사용 / Bobble에 사용 | 팬 위키 |

**확인된 Power Play**
- **Big Head**: Bobble 한 개의 머리가 커짐. 킥 파워는 세지고 이동은 느려짐
- **Ghosted**: 다음 턴 동안 Bobble 한 개가 다른 Bobble과 충돌하지 않음
- **Move Ball**: 공을 센터로 되돌리고 턴 타이머를 리셋
- **Move Player**: Bobble 한 개를 센터로 이동
- 이름만 확인된 것: Beach Ball, Swap Goals, Big Bumpers, Boost, Sticky Goo, Ramp

> 정확한 턴 시간, 경기 길이, 킥 판정 수치는 공개 자료가 없어서 아래 기획에서 우리가 직접 정함.
> 필드는 테이블 위 보드 형태이고 사방이 벽이라 공이 밖으로 나가지 않음 (플레이 영상 기준).

## 2. 우리 게임 핵심 정의

**한 줄 요약:** 선수 인형 4개를 동시에 튕겨서 큰 풋살 골대에 공을 넣는 턴제 물리 축구.

### 2.1 코어 루프
```
[계획 페이즈 12초] 내 알 4개에 드래그로 화살표 지정 (CPU도 동시에 계획)
        ↓ (시간 종료 또는 양쪽 "준비 완료")
[실행 페이즈 약 3초] 8개 알이 동시에 출발 → 충돌, 킥, 벽 튕김 → 모두 멈출 때까지
        ↓
[판정] 골이면 골 연출 후 킥오프 재배치 / 아니면 다음 턴
```
- 경기: **선취 3골 승리** 또는 **12턴 종료 시 다득점**. 동점이면 골든골 턴 추가
- 모든 알을 꼭 움직일 필요는 없음 (화살표를 안 그리면 제자리)

### 2.2 모드 (단계별)
1. **1차: vs CPU** (혼자 하기, 우선 구현)
2. 2차: 같은 기기 2인 (계획 화면을 번갈아 가리는 방식)
3. 3차: 온라인 1:1. 이미 쓰는 Firestore로 양쪽 입력을 받고 호스트가 결과를 확정 (동시 제출 구조라 실시간 서버 없이도 가능)

## 3. 경기장 규격 (풋살장 느낌, 큰 골대)

실제 풋살장은 40×20m, 골대 3×2m. 알 크기를 생각해서 비율을 바꿈 (게임 단위 1 = 1m 느낌).

| 요소 | 값 | 비고 |
|---|---|---|
| 필드 | **36 × 22** | 풋살 비율(약 2:1)보다 조금 넓게 해서 4:4가 덜 답답하게 |
| 벽 | 사방 펜스, 반발 0.8 | 풋살장 펜스 느낌. 공은 밖으로 안 나감 |
| 코너 | 반지름 2 라운드 처리 | 구석에 공이 끼는 것 방지 |
| **골대 폭** | **8** (필드 폭의 약 36%) | 실제 비율(15%)의 2배 이상. 득점이 자주 나오게 |
| 골대 깊이 | 2.5 | 골망 안쪽에 들어가면 득점 |
| 골포스트 | 반지름 0.3 원기둥 | 포스트 맞는 소리가 핵심 효과음 |
| 페널티 박스 | 반원 반지름 6 (표시만) | 규칙은 없고 보는 맛 |
| 알(Bobble) | 반지름 1.1, 질량 1.0 | 바닥은 원판, 위에 머리가 큰 인형 |
| 공 | 반지름 0.6, 질량 0.35 | 가벼워서 잘 튐 |

**포메이션 (킥오프)**: 골키퍼 1 + 수비 1 + 윙 2 (다이아몬드형). 골 먹은 팀이 센터에서 시작하고, 공은 정중앙.

## 4. 조작 / UI

- **드래그**: 알을 누르고 **반대 방향으로 당김** (새총). 놓으면 그 방향, 세기로 화살표가 고정됨
  - 최대 당김 거리 = 최대 파워. 화살표 길이 = 예상 이동 거리 (마찰 감안)
  - 화살표 색: 초록 → 노랑 → 빨강 (파워 단계)
  - 계획 중에는 화살표를 다시 잡아서 수정 가능, 알을 탭하면 취소
- **카메라**: 비스듬한 위쪽 고정 시점 (약 55도). 계획 페이즈는 전체가 보이게, 실행 페이즈는 공 쪽으로 살짝 줌, 골 순간 골대 쪽으로 펀치 줌
- **HUD**: 상단 스코어보드 (팀색 + 점수 + 남은 턴), 원형 타이머, 하단 "준비 완료" 버튼
- **모바일**: 세로 화면이면 필드를 회전해서 세로로 길게 표시. 터치 드래그 그대로 사용

## 5. 물리 설계

3D 물리엔진 없이 **2D 원 충돌 물리를 직접 구현**하고 화면만 3D로 그림. 알까기는 평면 운동이라 이게 더 가볍고, 결과를 똑같이 재현할 수 있어서 AI 예측과 온라인 확장에 유리함.

- 고정 타임스텝 **120Hz**, 서브스텝으로 빠른 공이 벽을 뚫는 문제 방지
- 마찰: 선형 감속 (알 `μ=9`, 공 `μ=5`) → 짧게 미끄러지고 딱 멈추는 알까기 느낌
- 충돌: 원-원 탄성 충돌 (반발계수 알-알 0.85, 알-공 0.9), 원-벽, 원-포스트
- **킥 보정 (핵심)**: 알이 공에 닿으면 순수 물리 충격에 **알의 진행 방향으로 추가 충격**을 더함 → "찼다"는 느낌. Big Head는 이 계수 ×1.6
- 정지 판정: 모든 속도 < 0.05가 0.3초 유지되면 실행 페이즈 종료 (최대 6초에서 강제 종료)
- 득점: 공 중심이 골라인을 넘어 골대 안으로 들어가면 즉시 득점 (그 이후 움직임은 연출로만 진행)

## 6. 타격감 (Juice) 설계

| 이벤트 | 연출 |
|---|---|
| 드래그 당기는 중 | 알이 당기는 쪽으로 **찌그러짐(squash)**, 머리가 뒤로 젖혀짐, 파워에 따라 미세 진동 |
| 출발 | 늘어남(stretch) 후 복원, 바닥에 먼지 링 |
| 알↔공 킥 | **히트스톱 50~90ms** (충격량 비례), 공에 흰색 플래시, 충격파 링, 카메라 흔들림(약), 공 뒤에 **트레일** |
| 알↔알 충돌 | 히트스톱 30~60ms, 접점에서 별 모양 파티클, 양쪽 머리가 **스프링으로 흔들흔들** |
| 벽 튕김 | 펜스가 살짝 휘었다 복원, 작은 먼지 |
| 골포스트 | 포스트 진동 애니메이션, 화면 흔들림(중), 짧은 슬로우 |
| 골 직전 | 공이 골라인 3 이내 + 빠르면 **슬로우모션 0.35배**, 비네트 |
| 골 | 골망이 출렁임(버텍스 변형), 화면 플래시, 팀색 **꽃가루**, 카메라 펀치 줌, 스코어 숫자 튀어오름, "GOAL!" 텍스트 팝 |
| 자책골 | 같은 연출 + "자책골..." 텍스트와 웃긴 효과음 (원작 재미 포인트 강조) |

- 모든 흔들림과 히트스톱에는 상한을 둬서 연속 충돌 때 멀미가 나지 않게 함
- "모션 줄이기" 설정이 켜져 있으면(`prefers-reduced-motion`) 흔들림과 슬로우 끔

## 7. 효과음 설계 (WebAudio 실시간 합성, 음원 파일 없음)

음원 라이선스 걱정이 없고 용량이 0이며, 충격 세기에 따라 소리를 연속적으로 바꿀 수 있음. 모든 소리는 **충격량에 따라 볼륨과 피치를 바꾸고** 재생할 때마다 피치를 ±5% 랜덤으로 줘서 반복감을 줄임.

| 소리 | 합성 방법 |
|---|---|
| 킥 "퍽" | 사인파 160→50Hz로 80ms 동안 하강 + 짧은 노이즈 클릭(하이패스 2kHz, 10ms) |
| 알 충돌 "딱" (플라스틱) | 삼각파 900Hz, 40ms 감쇠 + 밴드패스 노이즈 3kHz |
| 벽 "텅" | 사인파 110Hz + 로우패스 노이즈, 120ms |
| 골포스트 "땡~" | 비배음 3개(520 / 1340 / 2100Hz), 600ms 지수 감쇠 |
| 골망 "촤악" | 화이트노이즈 → 밴드패스 800→3000Hz 스윕, 400ms |
| 골 환호 | 노이즈 밴드패스 + LFO 진폭 흔들림, 2초 페이드 + 짧은 에어혼(톱니파 2개를 살짝 어긋나게) |
| 자책골 | 하강하는 "뿌우~" 트롬본 (톱니파 300→150Hz + 비브라토) |
| 휘슬 | 사인파 2.8kHz + 빠른 비브라토(30Hz), 킥오프 1회 / 종료 3회 |
| 드래그 당김 | 파워에 따라 올라가는 끼익 톤 (조용하게) |
| 타이머 | 마지막 3초에 틱, 0초에 "딩" |
| 발사 | 8개 동시 출발 시 "슝" 노이즈 스윕 1회 (동시에 겹치지 않게 묶음) |
| UI | 버튼 클릭 "톡" |

- 같은 종류 소리는 프레임당 최대 3개까지만 재생 (8개가 동시에 부딪힐 때 소리가 뭉개지지 않게)
- 마스터 컴프레서와 음소거 토글, 볼륨 설정은 localStorage에 저장
- 브라우저 정책상 첫 터치 때 AudioContext 시작

## 8. 비주얼 (간단한 3D)

- **Three.js** (CDN, 버전 고정) + 직접 만든 로우폴리 모델. 외부 3D 에셋 없음
- 알: 원판 받침 + 원통 몸통 + **큰 구 머리** (스프링 흔들림), 팀색 유니폼, 등번호 텍스처 (캔버스로 생성)
- 필드: 인조잔디 줄무늬 (캔버스 텍스처), 흰 라인, 투명한 펜스, 골망은 와이어프레임 메쉬
- 조명: 반구광 + 그림자 1개 (모바일에서는 그림자를 블롭으로 대체)
- 팀색: 홈 빨강 / 원정 파랑. 사이트의 Jua 폰트, 기존 카드 톤 유지

## 9. CPU AI

물리를 똑같이 재현할 수 있으니 **"여러 후보를 시뮬레이션해서 제일 좋은 걸 고르는"** 방식으로 함.

1. 알마다 후보 수 생성: ①공→상대 골 방향 슛 ②공을 걷어내기 ③골문 앞 막기 ④가만히 ⑤랜덤 약간
2. 상대 이동은 "가만히 있음"으로 가정하고 조합 약 40개를 앞으로 시뮬레이션
3. 점수 = 득점(+100) / 실점(−150) / 공과 상대 골 거리 / 골키퍼가 골문 앞에 있는지
4. 난이도: 쉬움은 후보 수를 줄이고 각도 오차 ±12도, 어려움은 후보 수를 늘리고 오차 ±3도
- 시뮬레이션 계산은 계획 페이즈 12초 안에 나눠서 돌려 프레임이 끊기지 않게 함

## 10. Power Play (초안, 16장 구상으로 대체됨)

턴마다 1개를 쓸 수 있고, 경기 시작 때 랜덤 3장 지급.

| 이름 | 효과 |
|---|---|
| 빅헤드 | 알 1개: 킥 ×1.6, 이동 ×0.7, 머리 2배 |
| 유령 | 알 1개: 이번 턴 알끼리 충돌 무시 (공과는 충돌) |
| 공 리셋 | 공을 센터로 + 타이머 리셋 |
| 부스트 | 알 1개: 최대 파워 ×1.4 |
| 끈끈이 | 필드에 원형 장판: 지나가는 물체 강한 감속 |

## 11. 파일 구조 (기존 `connect/`, `blackjack/`처럼 독립 폴더)

```
public/football/
  index.html      진입점, importmap(three)
  styles.css      HUD/메뉴
  app.js          상태 머신 (메뉴 → 계획 → 실행 → 골 → 결과)
  physics.js      2D 원 물리 (결정적, 렌더 독립)
  render.js       Three.js 씬, 모델, 카메라
  fx.js           히트스톱, 흔들림, 파티클, 슬로우모션
  audio.js        WebAudio 합성 효과음
  ai.js           CPU 시뮬레이션 AI
  input.js        드래그/터치 조준
```
- 허브 `public/index.html`에 커넥트처럼 `<a class="mode-card" href="bobble/">` 카드 추가 (⚽ "알까기 축구 · 4:4 바블 축구")
- 플레이 기록은 기존 `logPlay("bobble")` 패턴을 그대로 사용

## 15. 온라인 대전 (구현됨)

- **자동 매칭만**. 대기열에 2명 이상이면 들어온 순서대로 2명씩 묶는다. **20초** 안에 안 잡히면 CPU전으로 시작.
- 턴 시간 **15초**. 시간이 다 되면 그때까지 그린 화살표로 자동 제출 (실제 시계 기준이라 탭이 백그라운드여도 흐른다).
- 닉네임 없음, 교체 없음. 이모지 4개(👏 😂 😱 🔥)만 주고받는다. CPU전에서는 CPU가 가끔 반응한다.
- 유니폼: 각자 화면에서 **내 팀은 항상 홈 유니폼**, 상대만 색이 겹치면 원정 유니폼(그것도 겹치면 검정).
- 화면: 둘 다 자기 팀이 왼쪽(세로 화면이면 아래)에서 공격하도록 카메라를 뒤집는다.
- 나가기: 나가면 상대 기권승. 수를 낸 뒤 25초 동안 상대가 안 오면 나간 것으로 본다.

### 구조
- Firestore만 사용 (`public/football/online.js`). `bobbleQueue`(대기열), `bobbleMatches/{id}`(경기), `turns/{seq}`(양쪽 수, 즉시형 아이템, 방장 결과), `emotes`.
- 짝을 만든 쪽이 방장. 양쪽 수가 모이면 **방장이 그 자리에서 턴 끝까지 계산해 결과를 올리고**, 둘 다 화면 연출을 본 뒤 그 결과로 맞춘다.
- 공 리셋, VAR 같은 즉시형 아이템은 그 턴에 먼저 기록한 한 명만 인정 (트랜잭션).
- 로컬 테스트: `firebase emulators:start --only firestore` 후 `?emu`를 붙여 두 탭에서 접속.
- **배포 필요**: `firestore.rules`에 새 컬렉션 규칙을 넣었다. 배포 전에는 실서버에서 온라인이 동작하지 않는다 (20초 뒤 CPU전으로 넘어감).

## 16. 아이템 (구현됨)

- 2턴마다 필드 빈자리에 🎁 상자로 떠오른다 (최대 2개, 무슨 아이템인지는 먹어야 안다). **선수 몸이 닿으면** 그 팀이 가져간다 (공은 못 먹음). 최대 3개 보유.
- 계획 단계에서 **한 턴에 여러 개**도 쓸 수 있고, 누르는 순간 바로 적용된다 (상대 화면에도 바로 보임). 파워슛·레드카드는 커서가 아이템 모양으로 바뀌고 선수를 찍으면 적용.
- 겹쳐 쓰기: 비치볼·빙판은 누가 또 쓰든 2턴씩 연장. 파워슛은 이미 불붙은 선수에겐 못 씀. 골대 바꾸기는 바뀐 상태에서 또 쓰면 원래대로. VAR은 그 턴에 먼저 쓴 한 명만.
- 레드카드 🟥: 상대 선수 한 명(키퍼 포함)을 찍으면 이번 턴 동안 경기장에서 빠지고(`world.bench`), 턴이 끝나면 원래 자리(막혀 있으면 옆 빈자리)로 돌아온다.
- 온라인: 일반 아이템은 턴 문서 `hostItems`/`guestItems` 맵(시간순 키)에 쌓고 양쪽이 같은 순서로 적용. VAR만 `instant` 트랜잭션으로 선착순.
- 아이템을 누르거나 먹으면 설명 한 줄이 잠깐 뜬다. 아이템 칸은 항상 3칸(빈칸은 점선).
- CPU도 상자를 노리고 움직인다.

| 아이템 | 방식 | 효과 |
|---|---|---|
| 🔥 파워슛 | 출발형, 내 선수 선택 | 이번 턴 그 선수가 차면 공에 불이 붙어 아주 빨라지고(속도 26 이상, 마찰 거의 없음), 맞은 상대 선수는 공과 같이 벽까지 날아감 |
| 🏖️ 비치볼 | 출발형 | 2턴 동안 공 크기는 그대로, 가볍고 덜 멈추고 벽·선수에 맞으면 거의 그대로 튕김 (화면에서 통통 뜀) |
| 🔄 골대 바꾸기 | 출발형 | 이번 턴만 득점 판정이 반대로 (골망이 주황색) |
| 🧱 벽 세우기 | 위치 선택 (아이템을 끌어다 놓거나 누른 뒤 찍기) | 2턴 동안 원하는 곳에 폭 방향 벽 (길이 5.2) |
| 🎯 공 리셋 | 즉시 | 공을 센터로, 계획 시간 다시 15초 |
| 🧊 빙판 | 즉시 | 2턴 동안 경기장 전체가 미끄러움 (마찰 30%) |
| 📺 VAR | 즉시 | 직전 턴 시작으로 되감기 (점수 포함). 쓴 쪽만 다시 계획하고, 상대가 그대로 다시 할 이동이 빨간 화살표로 다 보인다. 아이템 상자와 가진 아이템은 되감지 않는다 |
| 🍯 끈끈이 | 출발형 | 이번 턴 우리 선수 몸에 공이 붙어서 같이 움직임. 거의 멈추거나 세게 부딪히면 떨어짐 |

CPU는 상황을 보고 쓴다 (실점 직후 VAR, 우리 골문 근처면 공 리셋이나 벽, 골키퍼 거인화 등).

## 17. 득점 쉽게 / 아이템 정리 (2026-10-25)

- 골대 폭 8 → **10**, 골키퍼 원판 0.9~1.15, 공 마찰 7.5 → 5.8, 킥 보정 0.22 → 0.30. 같은 슈팅 300번 기준 득점률 17% → 25%.
- 선공 없음: 매 킥오프마다 양 팀 모두 고른 포메이션 자리에서 시작.
- 처음 들어오면 아스날이 선택되어 있다.
- 조준 세기는 화면 픽셀 거리로 잰다 (터치: 짧은 변의 약 13.5%, 마우스: 24%). 세로 화면은 경기장 양옆에 여백. 벽에 붙은 선수도 최대로 당길 수 있다.
- 아이템은 모두 득점이 잘 나는 쪽으로: 벽 세우기, 끈끈이 삭제. 거인화는 필드 선수 전용 + 슈팅 1.8배. 공 리셋은 "찬스볼"(공을 상대 진영 한가운데로)로 변경.

- 골대 바꾸기는 2턴으로 통일. 각 골대 위에 그 골대를 지키는 팀 엠블럼 배지가 떠 있고, 바뀌면 두 배지가 포물선을 그리며 자리를 바꾼다 (충격파, 번쩍, "골대 체인지!" 배너, 소리). 2턴 뒤 원래대로 돌아올 때도 같은 연출. 턴 표시 아래에 걸린 효과와 남은 턴(🔄2, 🧊1) 칩.
- 골든골에서는 매 턴 상자 2개 (필드에 최대 4개).

- 아이템 재조정 (시뮬레이션 기준, 평균 능력치 한 번 슛 골 확률 기본 약 19%): 파워슛 약 35%, 비치볼 약 27%, 레드카드 약 28%, 빙판 약 27%.
- 찬스볼: 내 선수마다 골대 쪽 여러 각도·거리로 공 자리를 놓아 보고, 상대는 가만히 둔 채 실제로 차 봐서(약간 빗나간 슛 포함) 골이 제일 잘 나는 자리에 공을 놓는다. 난수가 없어서 온라인 양쪽이 같은 자리. 흩어진 판 기준 골 확률 약 8% → 약 65% (상대가 막으러 움직이면 실제로는 더 낮음).
